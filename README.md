# QALA LAB · Аким на 5 часов

Интерактивный симулятор управления Астаной для хакатона. Команда получает **1 000 000 000 ₸**, выбирает пять городских инициатив и видит, как меняются районные показатели и **Astana Quality of Life Score**. AI объясняет результат, сильные стороны и компромиссы.

Основание: [задание хакатона «Аким на 5 часов»](https://docs.google.com/document/d/1oDZtYnBgbcn_Ii7vleP87hkARJ2HmbXl7Cw_rsCxqpo/preview).

Инициативы основаны на опубликованных практиках Астаны; ссылки на официальные источники доступны под проектами. Объём предлагаемых пилотов, распределение по учебным районам, показатели, эффекты и цены синтетические. Схема районов не является географической картой. Проект не выдаёт расчёты за официальную статистику, реальную смету или доказанный прогноз.

## Быстрый запуск

Нужен **Node.js 22.13+** (SQLite встроен в Node). Проверено на Node 24.13.1.

```bash
npm ci
npm run dev
```

Откройте **http://localhost:5173**. API запускается на порту 3001. Если Vite выбирает другой порт, используйте адрес из терминала.

В Windows PowerShell с запретом запуска `npm.ps1` используйте `npm.cmd ci`, `npm.cmd run dev` и другие команды через `npm.cmd`. Менять политику безопасности PowerShell не нужно.

Production:

```bash
npm run build
npm start
```

Production-сайт и API доступны по **http://localhost:3001**.

## AI для защиты

Создайте `.env` по образцу `.env.example` и укажите собственный `OPENAI_API_KEY`. Не добавляйте ключ в репозиторий. После изменения переменных перезапустите сервер.

```env
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
OPENAI_BASE_URL=https://api.openai.com/v1
PORT=3001
```

Используется серверная интеграция с OpenAI-совместимым `/chat/completions`. Можно настроить совместимого провайдера через `OPENAI_BASE_URL` и `OPENAI_MODEL`. Ключ не передаётся в браузер. AI получает бюджет в KZT, расходы, выбранные проекты, эффекты, районные и городские показатели. Возвращает структурированный JSON с объяснением результата. Числовой Score всегда определяется моделью и не меняется языковой моделью.

**Без ключа работает локальная аналитика, а не AI.** Это явно отмечено на экране и в экспортируемом отчёте. При ошибке провайдера или тайм-ауте 18 секунд также включается локальный разбор. Для демонстрации обязательного AI-критерия подключите действующий ключ и проверьте, что над отчётом отображается «AI-АНАЛИЗ».

## Демо за 2 минуты

1. Откройте симулятор. Покажите исходный Score и бюджет 1 млрд ₸.
2. Выберите «Приоритет автобусов Bus Lane». Бюджет уменьшится на 240 млн ₸, транспорт района Алматы изменится с 48 до 61.
3. Переключите район на схеме и сравните его показатели. Нажатие на выбранный проект снимает выбор.
4. Выберите «Зелёные дворы у школ Астаны», «Безбарьерная среда в школе», «Свет на дворовых маршрутах», «Помощь с обращениями в iKOMEK109». Общая стоимость — **850 млн ₸**, резерв — **150 млн ₸**.
5. Нажмите «Рассчитать результат»: откроются сравнение до/после и разбор. При настроенном ключе источник — AI.
6. Зарегистрируйтесь в «Личном кабинете», вернитесь в аналитику и сохраните сценарий. Создайте новый, нажмите «Подобрать по модели», оцените и сохраните. Сравните результаты в «Мои сценарии».
7. Скачайте отчёт или выберите «Печать / PDF» в аналитике.

Для демонстрации резерва выберите тёплые остановки за 290 млн ₸. Проект озеленения Есиля за 280 млн ₸ станет недоступен: после двух проектов должно остаться не менее 460 млн ₸ на социальную инфраструктуру, безопасность и сервис. Выберите зелёные школьные дворы за 150 млн ₸ — все пять направлений можно завершить.

## Модель и валюта

Все денежные значения хранятся **целыми тенге**, интерфейс сокращает их до млн ₸. Масштаб исходного сценария: 1 исходная единица = 10 000 000 ₸. Это выбор масштаба учебной модели, не валютный курс. Существующие сохранения предыдущей версии автоматически пересчитываются в тенге при запуске; их отчёты заменяются актуальным локальным разбором.

Для каждого района исходный индекс направления имеет шкалу 0–100. Эффекты выбранных проектов суммируются, результат ограничивается диапазоном 0–100. Отрицательные эффекты сохраняются: например, транспортный хаб уменьшает озеленение Есиля на 2 пункта.

```text
Городской показатель = Σ(индекс района × население района) / Σ(население районов)
Score = Σ(городской показатель направления × вес направления)
```

| Направление | Вес |
| --- | ---: |
| Транспорт | 25% |
| Озеленение | 20% |
| Социальная инфраструктура | 20% |
| Безопасность | 20% |
| Городской сервис | 15% |

Промежуточные значения для Score не округляются. Отображаемые показатели, Score и прирост округляются до одного знака; из-за этого разность отображаемых чисел может отличаться от отображаемого прироста на 0,1. При равном отображаемом Score подбор предпочитает более дешёвый набор.

## Архитектура

**React 18 + Vite** — интерфейс, навигация, адаптивная сетка. **SVG и CSS** — схема города и диаграммы, без картографических ключей и тяжёлых библиотек. **Lucide** — иконки. **Express** — API и production-раздача. **SQLite / node:sqlite** — сохранения. **node:test** — проверки без дополнительного тестового фреймворка.

Браузер и сервер используют одну чистую функцию расчёта. Браузер немедленно обновляет показатели; сервер заново проверяет ID инициатив, уникальность направлений, количество решений и лимит при анализе и сохранении. Суммам и Score из клиента сервер не доверяет.

```text
src/ui/App.jsx        Интерфейс, схема, аналитика, история и экспорт
src/ui/styles.css     Адаптивный дизайн и стили печати
src/shared/model.js   Общий расчёт Score и подбор комбинации
server/index.js      API, AI-провайдер, SQLite и миграция
data/scenario.json   Синтетические данные, цены KZT, эффекты, веса
tests/model.test.js  Бюджет, валидация, эффекты, оптимизация
tests/api.test.js    Аккаунты, изоляция и перезапуск с временной SQLite-БД
```

`data/astana-simulator.sqlite` создаётся автоматически и исключена из Git. Для тестов поддерживается `DATABASE_PATH=:memory:`. Новые аккаунты используют почту, имя и пароль. Старые аккаунты могут входить по прежнему логину. Пароли хешируются scrypt с индивидуальной солью. Сессии хранятся в SQLite, браузер получает HttpOnly / SameSite=Strict cookie на 30 дней. Для HTTPS-развёртывания задайте COOKIE_SECURE=true. Профиль, черновик и история доступны только владельцу. Старые демо-профили сохранены в БД, но не привязываются автоматически к новым аккаунтам по публичному ID.

## Проверки

```bash
npm run build
npm test
```

Девять тестов проверяют единый бюджет, отказ при перерасходе и неправильных ID, влияние решений, отрицательные эффекты, независимость от порядка выбора, оптимальность среди 243 комбинаций и API-проход «расчёт → анализ → профиль → сохранение → история». API-тест использует порт 19371 и отдельный временный SQLite-файл, не меняя пользовательские сохранения. Он проверяет регистрацию, пароль, вход/выход, запрет доступа к чужому профилю, черновик и сохранение данных после перезапуска сервера. Дополнительный тест перебирает все 1024 частичных комбинации и проверяет возможность завершить каждую разрешённую. Вызов внешнего AI тестами не выполняется: для него нужен действующий ключ и доступ к провайдеру.

На момент обновления production-сборка и все 9 тестов прошли. Визуальная проверка в браузере не выполнена: в среде разработки не был подключён браузер автоматизации.

## Дальнейшее развитие

Сравнение команд и восстановление паролей; калибровка весов с городскими экспертами; реальные пространственные данные; интервалы неопределённости эффектов; сценарии неожиданной нагрузки. Эти функции требуют отдельных данных и проверки модели, поэтому не подменяются случайными числами в текущем прототипе.

## Личный кабинет и сохранение

1. Откройте «Личный кабинет» → «Регистрация», укажите почту, имя и пароль от 8 символов. Почта проверяется и в браузере, и на сервере: обязательны @ и домен, пробелы и пустые части адреса запрещены. Имя, пароль и почта поддерживают кириллицу. Формат проверяется, но письмо подтверждения пока не отправляется.
2. Измените имя в профиле. После входа история привязана к аккаунту, а не к устройству.
3. Сохраните незаконченный набор кнопкой «Сохранить текущий план» в кабинете. «Продолжить черновик» восстановит его. Сохранение черновика выполняется явно, не автоматически.
4. Завершённые сценарии сохраняются кнопкой в аналитике. Выйдите и войдите снова: профиль, черновик и история останутся.

Восстановление забытого пароля пока не реализовано. Новый аккаунт не импортирует предыдущую незащищённую демо-историю. Симулятор и локальная аналитика доступны гостям.

Новые API: POST /api/auth/register (email, password, nickname), POST /api/auth/login (email, password; для старых аккаунтов — login, password), POST /api/auth/logout, GET /api/auth/me, GET/PUT /api/account/draft (selectedIds). Запросы профиля и сохранений требуют действующей сессии владельца. Данные хранятся в таблицах profiles, accounts, sessions, drafts, scenario_runs.

## Почему денег хватает на пять решений

При каждом выборе считаем не только уже потраченное, но и минимальную стоимость одного проекта в каждом ещё пустом направлении. Выбор допускается только если расходы + этот резерв ≤ 1 млрд ₸. Сам бюджет не увеличивается: дорогие комбинации могут быть недоступны, но после любого разрешённого выбора остаётся хотя бы один полный вариант из пяти решений. Правило одинаково в браузере и API.
